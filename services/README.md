# Services

Go backend for the agentic bank. One binary, `cmd/bankd`.

```
chain events ─► indexer ─► bank (sink) ─► ledger (double-entry books)
agent ─► api ─► bank ─► orchestrator gates ─► preflight (on-chain policy dry-run) ─► relayer ─► chain
```

| Package | Responsibility |
|---|---|
| `ledger` | Double-entry books: balanced entries per asset, holds, overdraft protection, idempotent posting, reversals |
| `orchestrator` | Payment state machine with bank control gates: validate → hold funds → screen → sign/co-sign → broadcast → confirm → reconcile → settle; plus held, exception and returned paths |
| `chain` | ABIs (generated by `scripts/gen-abi.sh`), typed event decoding, contract reads (`wouldAuthorize`, session keys, digests), the relayer |
| `indexer` | Follows confirmed blocks in chunked ranges and tracks accounts opened mid-range. Delivery is at-least-once, so sinks are idempotent |
| `bank` | The sink (Transfer → ledger postings; PaymentExecuted → settle orchestrated payments) and the signing and broadcast gates |
| `api` | REST gateway; endpoints are listed in `api/api.go` |
| `internal/testchain` | Deploys the real contracts on go-ethereum's in-process simulated chain for integration tests |

## Books

Each AgentAccount and token has two ledger accounts:

- `wallet:<account>:<token>` (asset): tokens held on-chain.
- `funds:<account>:<token>` (liability): owed to the account owner.

Deposits and payments move both together, so reconciliation is exact: books must equal `balanceOf`. Payments submitted through the API reserve a ledger hold first. The orchestrator posts them when the chain event arrives, and the indexer doesn't book them a second time.

## Agent payment flow

1. The agent builds a `PaymentIntent` with `ref = keccak256(paymentId)` and signs its EIP-712 digest with its session key.
2. `POST /v1/payments` places a hold, verifies the session key, and dry-runs `PolicyEngine.wouldAuthorize`. If the payment needs a co-signature it parks as `awaiting_cosign`; otherwise it is relayed.
3. The indexer sees `PaymentExecuted` and the orchestrator posts and reconciles it, ending in `settled`.

## Run

```bash
go test -race ./...          # unit + integration (simulated chain, real contracts)
go run ./cmd/bankd           # needs BANK_* env vars, see cmd/bankd/main.go
```
